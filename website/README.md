# berg:work website v2

Production-oriented static product site for the two berg:work desktop apps. It is generated by a zero-dependency Node 22 build and makes no third-party runtime requests.

## Information architecture

| Route | Purpose |
| --- | --- |
| `/` | What berg:work is in one screen (two buttons into the web apps), one short take per product, how files stay local, who makes it. |
| `/pdf/` | berg:work PDF: its take, one small screenshot per tool with a short explanation, measurements, honest notes, desktop status. |
| `/image/` | berg:work Image: the same structure, plus what it will not do. |
| `/roadmap/` | Status of both products without unsourced dates. |
| `/download/` | “Desktop” in the navigation: nothing to install, desktop status; release-manifest-driven downloads once they exist. |
| `/legal/` | English legal notice preserving the provider and contact facts. |
| `/privacy/` | English privacy information including hosting, logs and service-worker storage. |
| `/offline/` | Offline fallback reached by the service worker. |
| `/404.html` | Not-found page for static hosting. |

## Build and preview

Node 22 is the only build dependency. From `website/`:

```bash
node build.mjs
node serve.mjs
```

The build writes clean routes and the root `404.html` to `dist/`. The preview defaults to `http://127.0.0.1:8080/` and serves `.webmanifest`, `.woff2`, images and video with explicit MIME types. For rebuild-on-change:

```bash
node build.mjs --watch
```

### Web apps

`build.mjs` also builds the browser editors and copies them under `/app/`: berg:work Image from `apps/image` to `/app/image/` (Vite with `BERGWORK_BASE=/app/image/`) and berg:work PDF from `apps/pdf` to `/app/pdf/` (`apps/pdf/scripts/build-frontend.mjs`, relative paths). Missing dependencies are installed first (`npm ci` for the `packages/ui` and `apps/pdf` workspaces and in `apps/image`, and the PDF editor's pinned build with `scripts/sync-upstream.mjs install`, which takes it from the `upstream/fernwork-pdf/<commit>` tag of this repository when no Fernwork checkout is there), so Workers Builds needs no extra install step; the first local build takes a few minutes. After a new PDF pin, publish its tag before pushing `main`: `npm run sync:publish -- fernwork-pdf`. `BERGWORK_SKIP_APPS=1 node build.mjs` builds the site alone. `_headers` gives `/app/image/*` and `/app/pdf/*` their own CSP (WebAssembly, blob workers, inline style attributes; Hugging Face model downloads for Image) and cross-origin isolation; the site's service worker leaves `/app/` alone. Files above the host's 25 MiB limit (ONNX Runtime's WebAssembly) ship gzip-compressed and are inflated by the editor.

`serve.mjs` does not apply `_headers`; test the apps with `npx wrangler dev` from `website/`.

`site.config.mjs` is the single source for the site name, canonical origin, contact address, colours and product names. `siteUrl` is `https://bergwork.app`; if it is ever emptied, the build warns and omits canonical URLs, `og:url` and `sitemap.xml`.

## Content evidence

`CLAIMS.md` is the publication ledger. Every product feature, status, format, platform, number, pricing/licence statement and privacy fact is linked to repository evidence and labelled `WORKS`, `IN PROGRESS`, `PLANNED`, `OWNER` or `CONFIRM`.

## Media

`content/media.json` defines every screenshot and video slot. Missing files are omitted from HTML and reported as build warnings. The complete capture brief is in `MEDIA.md`.

To add media, place it in `src/media/` using the name in the manifest, then rebuild. Screenshot WebP companions are used automatically when present. A video slot is rendered only when both the MP4 and its poster exist.

## Releases

## PWA and caching

The build fingerprints CSS, JavaScript, fonts, hero images, icons and present media. `_headers` gives `/assets/*` a one-year immutable cache and keeps HTML, the manifest and service worker on `no-cache`.

Open Graph pictures are JPEGs drawn by `media/og-images.py` (site, PDF, Image). Besides their fingerprinted copies under `/assets/img/`, the build writes stable copies to `/og/`, which the web apps' own pages link.

The generated service worker precaches the application shell, uses network-first navigation with `/offline/` as fallback, and keeps a capped stale-while-revalidate cache for same-origin images and media. The privacy page documents this local Cache Storage use.

## Cloudflare settings

The site is served by the `bergwork` Worker (static assets from `./dist`) on the custom domain `bergwork.app`, with `404.html` as the not-found page. Both are set in `wrangler.jsonc`.

Cloudflare Workers Builds deploys every push to `main` automatically; other branches get preview builds. The Git connection lives in the Cloudflare dashboard with:

- Root directory: `website`
- Build command: `node build.mjs`
- Deploy command: `npx wrangler deploy`

A manual deploy from `website/` is `node build.mjs && npx wrangler deploy`.

`www.bergwork.app` is served by the separate `bergwork-www-redirect` Worker in `www-redirect/`, which answers every request with a 301 to the same path on `bergwork.app`. It is not part of Workers Builds; deploy changes to it by hand with `npx wrangler deploy` from `website/www-redirect/`.

## Visual assets and font licence

The four mine heroes remain the identity images. Each has 2880×1620 and 1440×810 JPEG and WebP variants. The home page chooses one per load in `hero.js` and preloads exactly that picture at the size the stylesheet will use (the build fills in the URLs); without JavaScript it shows `mine-dusk`. Mobile CSS keeps the existing per-image focal crop. Below 980 px the hero is a column (wordmark, stickers, buttons), so the buttons are on the first screen of a phone.

Text is set in JetBrains Mono (SIL OFL 1.1, `src/assets/fonts/OFL-JetBrainsMono.txt`), a variable-weight Latin WOFF2 of about 40 KB, so the site looks the same on every system.

`Bergschrift-Regular.ttf` is a modified Stalinist One by Alexey Maslov and Jovanny Lemonad under the SIL Open Font License 1.1 (`src/assets/fonts/OFL.txt`). The Reserved Font Name required the Bergschrift rename. The site uses a WOFF2 containing the complete Latin-1, Latin Extended-A, Cyrillic and General Punctuation ranges from the source font. The source TTF remains available for regeneration with `../scripts/build-wordmark-font.py`.

The red/cream/ink palette, ruled grids, square corners, hard offset shadows, mine imagery and mountain mark carry forward from v1. Motion is limited to short hover/focus transitions and is disabled under `prefers-reduced-motion`.
